---
title: "Workflow: Market Analysis"
description: "Agent-friendly workflow to analyze a Polymarket market before execution."
---

## Goal

Produce a repeatable, machine-friendly market brief before placing a trade:

- current market state
- liquidity and spread context
- execution impact estimate
- explicit go/no-go and constraints

## Inputs

- `condition_id` (required)
- optional thesis horizon (`intraday`, `1d`, `1w`, `event_horizon`)
- planned side (`BUY` or `SELL`)
- intended size in USDC

## Recommended tool sequence

### 1) Pull market and event context

- `get_market` with `condition_id`
- `get_event` from related event id (if available)

Capture status, outcomes, timing, and any obvious event risk windows.

### 2) Check price and liquidity state

- `get_midpoint`
- `get_spread`
- `get_last_trade_price`
- `get_order_book`

Focus on:

- spread regime (tight/normal/wide)
- visible depth near midpoint
- recent print vs midpoint divergence

### 3) Estimate execution impact

Run `calculate_market_price` for your intended side and amount.

```json
{
  "tool": "calculate_market_price",
  "input": {
    "token_id": "<target_token_id>",
    "side": "BUY",
    "amount": "250",
    "order_type": "FOK"
  }
}
```

Use the result to set max slippage and an initial limit price.

### 4) Gather market metadata constraints

- `get_fee_rate_bps`
- `get_tick_size`
- `get_neg_risk`

These values should flow directly into order validation and execution policy.

### 5) Return standardized output

Have the agent produce a strict structure like:

```json
{
  "thesis": "short rationale",
  "confidence": 0.0,
  "market_state": {
    "status": "active|closed|...",
    "midpoint": 0.0,
    "spread": 0.0,
    "last_trade": 0.0
  },
  "execution": {
    "side": "BUY",
    "amount_usdc": "250",
    "estimated_price": 0.0,
    "max_slippage_bps": 0,
    "suggested_limit_price": 0.0
  },
  "risks": ["liquidity", "event timing"],
  "go_no_go": "GO|NO_GO",
  "fallback_plan": "what to do if liquidity degrades"
}
```

## Optional: use the built-in prompt

You can bootstrap this workflow by invoking prompt `market-analysis` with:

- `condition_id`
- `horizon`
- `include_orderbook_depth`
- `include_recent_trades`

The prompt already encodes the same high-level sequence and expected output shape.

## Execution handoff

If the brief returns `GO`, hand off to trading flows with:

1. explicit limit/size constraints
2. `confirm: true` only at final execution step
3. post-trade verification (`get_open_orders`, `get_user_trades`, optional websocket burst)
